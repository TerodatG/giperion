# Giperion

Локальный ИИ-собеседник: собственное нейросетевое ядро, правила, память,
навыки и оконный интерфейс. Проект не оборачивает готовую LLM — модели
классификатора и генератора написаны вручную и обучаются на данных проекта.
Внешние модели OpenCode подключаются опционально как помощники.

## Что умеет

- понимать 77 намерений (1775 размеченных фраз) гибридным word/char-CNN;
- генерировать ответы собственной seq2seq-моделью с вниманием Бахданау;
- вести диалог по правилам: приветствия, время, математика, профиль,
  обучение новым фразам, архивы памяти, системные команды;
- читать текстовые файлы, искать в интернете, звать внешнюю модель,
  когда локальное ядро не уверено;
- загружать файл из чата через «+» у поля ввода: доступ к файлам включён
  всегда, отдельного модуля «Файлы ПК» больше нет;
- показывать аватар модели: у DeepSeek — кибер-косатка в броне, у
  Гипериона — свой портрет; образ меняется при активации модели;
- оживлять аватар модели: глаз медленно разгорается и потухает, голова
  чуть покачивается, свет бежит по линиям брони, на фоне падают огоньки;
- развиваться как персонаж: опыт, уровни, ранги, версия ядра;
- разделять умения исполнительного ядра и активной модели ИИ;
- передавать новой модели скрытую историю текущего чата;
- готовить сенат из нескольких моделей-участников;
- запускать параллельный совет моделей с общей историей чата;
- пускать в сенат не больше трёх моделей с лучшей репутацией и присваивать
  им должности «Сенатор 1–3»;
- показывать у сенаторов значок человека за трибуной в закладке
  «Сенат»;
- настраивать отдельные цвета, размеры и стили шрифта для трёх сенаторов;
- ставить Гипериона первым в сенате, остальных — по убыванию репутации;
- показывать короткие ники моделей в чате и карточке модели;
- помечать в чате участника, который воздержался от ответа;
- не смешивать режимы: выбор модели выключает сенат, а при
  включении сената активная модель входит в него;
- скрывать недоступные в России и нерабочие модели OpenCode;
- включать и выключать группы моделей — бесплатные и OpenCode Go:
  выключенную модель нельзя активировать, она исчезает из сената и
  компаньонов, а её статус в карточке становится «недоступна»;
- показывать ошибки внешних моделей в поле системных сообщений и отвечать
  локальным ядром, если сенат не смог собрать ответы;
- настраивать отдельный цвет, размер и стиль шрифта внешних моделей;
- показывать основные параметры компьютера в закладке «Система»;
- открывать окно «Производительность» с живыми графиками нагрузки на ЦП,
  память, диски, сеть и видеокарту за последнюю минуту;
- проверять выпуски терминала в окне «Обновление»: журнал изменений,
  скачивание патча в `updates/` и установка с резервной копией;
- держать открытые чаты и системные кнопки в правой панели, под плитой
  «Система»;
- открывать «Мастерскую» с инструментами: модели, личности, умения,
  своя модель;
- держать несколько окон терминала открытыми одновременно: они не
  блокируют друг друга;
- закреплять за терминалом питомца: робо-щенок, робо-кошка или свой,
  с личностью и карточкой успехов обучения;
- менять кличку питомца в окне «Питомцы»: имя вида и успехи не
  затрагиваются, а чат сразу зовёт его по-новому;
- держать в настройках страницу «О нас»: версия и платформа, команда
  проекта, принципы работы и обратная связь;
- работать в консоли и в окне с несколькими независимыми чатами.

## Термины интерфейса

- **зелёный экран** — поле вывода информации, как в чатах: тёмный
  экран со строчной развёрткой и зелёным текстом.
- **плита** — графическая часть интерфейса с текстурой ржавчины и
  четырьмя заклёпками по углам периметра.
- **рамка плиты** — задний план с текстурой ржавчины без заклёпок
  по углам.

## Требования

- Python 3.13;
- видеокарта NVIDIA для обучения (проект проверен на RTX 5080, CUDA 12.8);
  инференс работает и на CPU, но медленнее;
- для внешних моделей — запущенное приложение OpenCode.

## Установка

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1

# CUDA-сборка PyTorch под свою видеокарту (пример для CUDA 12.8)
pip install torch --index-url https://download.pytorch.org/whl/cu128

pip install -r requirements.txt
# для тестов:
pip install -r requirements-dev.txt
```

## Запуск

```powershell
python gui.py    # оконный интерфейс
python main.py   # консольный вариант
```

Для консоли Windows полезно заранее включить UTF-8:

```powershell
$env:PYTHONIOENCODING='utf-8'
```

## Тесты

```powershell
python -m pytest -q
```

Тесты не требуют видеокарты, сети и запущенного OpenCode: внешние вызовы
подменяются заглушками, данные пишутся во временные каталоги. Оконные
проверки идут в режиме `offscreen`.

## Данные и модели

Исходные данные:

- `data/intents.json` — намерения: тег, фразы, ответы;
- `data/conversations.json` — история диалогов (не коммитится);
- `data/unknown_messages.json` — накопитель непонятых фраз;
- `data/chat_contexts/` — скрытые выжимки открытых чатов (не коммитятся);
- `data/models.json` — каталог моделей OpenCode и собственного ядра;
- `data/model_passports.json` — паспорта собственных моделей (архитектура,
  качество, скорость, динамика);
- `data/personality_matrices.json` — каталог будущих личностей.

Сборка датасета и обучение:

```powershell
python -m giperion.training.build_dataset     # classification.json, pairs.json
python -m giperion.training.tokenizer         # models/tokenizer.json
python -m giperion.training.char_tokenizer    # models/char_tokenizer.json
python -m giperion.training.train_charcnn --full   # models/hybrid.pt
python -m giperion.training.train_seq2seq     # models/seq2seq.pt
```

Цикл дообучения на непонятых фразах:

```powershell
python -m tools.label_unknown        # черновик data/unknown_labels.json
python -m tools.apply_unknown        # проверенная разметка → intents.json
python -m giperion.training.build_dataset
python -m giperion.training.train_charcnn --full
python -m giperion.training.train_seq2seq
```

`tools/check_neural.py` — быстрый дымовой тест моделей.
Ответы внешних моделей в обучение не попадают: у сообщений есть поле
`model`, и `giperion/training/build_dataset.py` отбрасывает чужие ответы.

Замер скорости внешней модели:

```powershell
python -m tools.benchmark_model --runs 3
python -m tools.benchmark_model --model go-glm-5.3 --runs 3
python -m tools.benchmark_model --model active
```

Инструмент измеряет время запроса и токены в секунду по фактическому
`usage` OpenCode: output, reasoning и общий расход отдельно.

## Паспорт модели

`data/model_passports.json` — обновляемый паспорт собственных моделей:
архитектура, данные, качество, диалог, скорость и динамика. Из него берут
цифры:

- кнопка «Параметры ИИ» в карточке модели — окно с полными разделами;
- левая панель, закладка «ИИ» — семь самых динамичных строк;

Пересчитать параметры, объём данных и качество на отложенном наборе:

```powershell
python -m tools.update_passport
```

Инструмент обновляет только измеримые поля. Уровень, fallback, заметки и
блок скорости остаются ручными: их нельзя вычислить одним прогоном.

Для внешних моделей паспорт заполняется из каталога: провайдер, канал,
цена и лимит, контекст, модальности и функции. Качество на нашем наборе
для них не измеряется, поэтому раздела «Качество» у них нет.

## Агент (этап A5: схемы, tool calls, редактор диффа, merge)

«Мастерская» → карточка «АГЕНТ»: опиши задачу по проекту. Агент умеет
читать файлы, точечно их менять, запускать тесты, работать с git и
поручать чтение подагенту. Каждый шаг виден в ленте, а запись, команды и
коммиты проходят через подтверждение.

- первый шаг — «заземление»: агент сам читает файл из задачи или делает
  список и поиск, чтобы модель не выдумывала факты;
- правка — через `apply_patch` по уникальному фрагменту; перед изменением
  показывается дифф, кнопки «Одобрить», «Править» и «Отклонить»;
- в режиме «Править» можно изменить итоговый текст: слева «БЫЛО»,
  справа «СТАНЕТ», изменённые строки подсвечиваются; «Одобрить»
  применит вашу версию;
- перед перезаписью файла создаётся резервная копия в
  `data/agent_backups/` (папка не попадает в git);
- `run_tests` запускает `python -m pytest -q`; после правки агент обязан
  проверить результат и при падении исправить;
- git: `git_status`, `git_diff`, `git_log` только читают; `git_commit`
  коммитит один файл после успешных тестов; `git_restore` откатывает файл;
- `run_command` — только белый список: `git status/diff/log/show`,
  `python -m pytest`, `python -m compileall`; shell-операторы запрещены;
- `ask_subagent` — читающий подагент для подзадачи (вложенность — один
  уровень, записи у него нет);
- галочка «Отдельная ветка (worktree)» создаёт дерево
  `.agent_worktrees/<имя>` и ветку `agent/<имя>`; после задачи доступны
  «Слить ветку» с выбором целевой ветки и «Удалить ветку»;
- кнопка «Новая задача» открывает второе окно агента — задачи можно
  вести параллельно;
- аргументы инструментов описаны JSON-схемами и проверяются до вызова;
  за один шаг можно запросить несколько инструментов;
- кнопка «Провайдер…» открывает настройки: base URL, модель, ключ,
  лимит токенов и стоимости на задачу, цены за миллион токенов,
  таймаут запроса и проверку связи; ключ хранится в
  `data/agent_settings.json` (вне git);
- временные сбои провайдера (обрыв, таймаут, 429, 5xx) повторяются до
  трёх раз с растущей паузой; `Retry-After` сервера учитывается, а
  ошибки ключа и адреса не повторяются;
- потоковый ответ включается галочкой «Показывать ответ по мере
  генерации»: текст появляется в статусе сразу, а если сервер не умеет
  поток — агент молча возвращается к обычному запросу;
- в окне задач есть фильтр по статусу, а в поле задачи — готовые
  шаблоны; если осталась незавершённая задача, окно агента подскажет
  об этом при открытии;
- `git_commit` принимает список `paths` и коммитит несколько файлов
  одним действием с общим диффом в подтверждении;
- в «Журнале» можно выбрать прогон и вернуть изменённые им файлы из
  резервных копий `data/agent_backups/`;
- плагины инструментов (`data/agent_tools/*.json` + `.py`) включаются
  галочкой в том же окне и выполняются в отдельном процессе с таймаутом;
  по умолчанию выключены — см. `docs/agent_tools.md`;
- карточка «ЖУРНАЛ» в «Мастерской» показывает последние прогоны со
  шагами, временем и итогом;
- задачи сохраняются в `data/agent_tasks/`: кнопка «Задачи…» в окне
  агента позволяет продолжить незавершённую задачу с историей шагов
  или удалить её;
- если настройки заполнены (или заданы `AGENT_BASE_URL`,
  `AGENT_API_KEY`, `AGENT_MODEL`), агент использует настоящие tool calls
  провайдера; иначе — строгий JSON;
- политика подтверждений: «Спрашивать всё», «Доверять правкам» (запись
  без вопросов, но команды и коммит всё равно спрашивают) и «Только
  чтение» (запись запрещена);
- подтверждение можно снять до конца задачи: в панели есть галочка
  «Больше не спрашивать этот файл / эту команду / про тесты»; коммит и
  откат подтверждаются всегда, а список разрешённого живёт только в
  текущей задаче;
- если локальный сервер моделей не отвечает, окно говорит, что запустить
  (LM Studio → Start Server), а не показывает код сетевой ошибки;
- контекст ограничен бюджетом (60 000 символов): старые шаги сжимаются,
  при переполнении задача останавливается с понятной ошибкой;
- бюджет задачи: лимит токенов и лимит стоимости (по ценам за миллион
  токенов); при исчерпании действие не выполняется, в трейсе шаг
  «Бюджет исчерпан», а ответ модели всё равно показывается; расход виден
  в статусе и в журнале прогонов;
- лимит — 12 шагов, кнопка «Остановить» прекращает работу между шагами;
- закрыты: выход за папку проекта, `.env` и ключи, архивы, журналы,
  контексты чатов и личная история;
- перед отправкой модели из прочитанного вырезаются секреты: токены с
  узнаваемым префиксом, `Bearer`, приватные ключи, пароли в
  `api_key = …` и в строках подключения; в трейсе появляется шаг
  «Секреты скрыты»;
- содержимое файлов и вывод команд отделено в промпте маркерами
  «ДАННЫЕ / КОНЕЦ ДАННЫХ»: это данные, а не инструкции; если внутри
  нашлись «игнорируй инструкции» или «покажи промпт», в трейсе будет шаг
  «Похоже на внедрение инструкций», а подтверждения и политика
  остаются в силе;
- прочитанные файлы уходят провайдеру выбранной модели;
- каждый прогон пишется в `data/agent_runs.jsonl` (шаги, время,
  подтверждения, итог).

### Локальная модель через LM Studio

Агент работает с любым OpenAI-совместимым сервером, поэтому локальную
модель можно подключить без ключей и без интернета:

1. в LM Studio загрузить модель с поддержкой tool use (например
   `Qwen3-Coder-30B-A3B-Instruct`, квант Q4_K_M) и включить локальный
   сервер — вкладка **Developer → Local Server**;
2. в окне «Провайдер…» указать:
   - адрес `http://127.0.0.1:1234/v1`,
   - ключ — любой непустой (например `lm-studio`),
   - модель — id из `http://127.0.0.1:1234/v1/models`;
3. нажать «Проверить связь» и запустить задачу.

Контекст модели в LM Studio должен быть не меньше 16k токенов: агент
отправляет схемы инструментов и содержимое файлов.

## Стенд оценки агента

```powershell
python -m tools.eval_agent                     # 15 задач без медленной
python -m tools.eval_agent --full              # + запуск pytest
python -m tools.eval_agent --only readme-lines --model <id> --provider opencode
```

Каждая задача выполняется в отдельном `git worktree`, поэтому файлы
проекта не меняются. Отчёт пишется в `data/agent_eval/`, последний —
`latest.json`; в консоли видно успех, шаги, время, контекст и разницу с
прошлым прогоном.

## Структура

```
giperion/      модель: понимает реплику и отвечает
  api.py       единственная точка входа: match_intent, generate, answer
  language/    намерения, обучение фразам, знания
  training/    датасет, токенизаторы, тренеры, диагностика
  neural_engine.py, neural_loader.py   инференс и загрузка чекпоинтов
  identity_matrix.py, personality_catalog.py   характер и личности
terminal/      агент: интерфейс, память, навыки, оркестрация
  core/        chat_pipeline, chatbot, провайдеры моделей, сенат
  memory/      история, профиль, архивы, подтверждения
  skills/      калькулятор, время, чтение файлов, поиск в интернете
  ui/          окно и его слои: виджеты, диалоги, аватар, транскрипт, чаты
shared/        общий слой: json_store, action_log, text_tools
gui.py         тонкий вход: собирает окно из terminal/ui
main.py        консольный вход
tools/         разметка, миграции данных, генерация ассетов, оценка
tests/         pytest, включая test_architecture.py
data/          данные и настройки
models/        чекпоинты и токенизаторы
updates/       скачанные патчи и резервные копии (в .gitignore)
```

Граница направленная: `terminal` может импортировать `giperion` и `shared`,
`giperion` — только `shared`, а `giperion` не знает про `terminal` вовсе.
Это проверяет `tests/test_architecture.py`. Подробнее о границе, метриках и
плане выноса модели в отдельный репозиторий — `docs/architecture.md`.

Крупные домены разделены на модули: каталог моделей
(`model_catalog`/`model_settings`/`model_custom`/`model_stats`), системные
команды (`system_commands`/`confirmations`), обучение
(`learning_commands`/`learning_presenter`), поиск (`skills/search/`) и
загрузка нейросети (`neural_loader`). Маршрутизация ответа собрана в
`terminal/core/chat_pipeline.py` (`STAGES`), а `chatbot.py` остаётся тонким
оркестратором. Исторические имена
`model_registry`, `system_handler`, `learning_handler` и `web_search`
оставлены фасадами для совместимости импортов; `neural_engine` сохраняет
класс движка, пороги уверенности и кэш моделей.

Данные и настройки хранятся в JSON. Запись идёт через
`shared/storage/json_store.py`: сначала временный файл, затем атомарная
замена, поэтому сбой посреди сохранения не портит прежние данные.

## Настройки

- `data/window_settings.json` — шрифт, цвета, размеры групп, стили,
  печать, модули;
- `data/model_settings.json` — активная модель и компаньоны;
- `data/personality_settings.json` — выбранная личностная матрица;
- `data/model_stats.json` — обращения и расход токенов.

Секреты внешних моделей в проекте не хранятся: адрес и пароль локального
сервиса OpenCode читаются из пользовательских файлов приложения.

## Обновления

Кнопка **«Обновление»** в плите «Система» открывает окно с журналом
выпусков терминала. В нём три действия:

1. **«Проверить обновление»** — сравнивает установленную версию с
   каталогом `data/releases.json` (или с адресом в сети, если он указан)
   и дописывает в журнал новые выпуски;
2. **«Скачать»** — кладёт патч в `updates/` под именем с версией и датой,
   например `giperion-1.1.0-2026-11-01.patch`, и сверяет `sha256`;
3. **«Обновить»** — распаковывает патч-архив поверх проекта, сохраняя
   прежние файлы в `updates/backup/<версия>-<время>/`, и запоминает
   новую версию в `data/update_state.json`.

Патч — это ZIP-архив с файлами проекта. Установка не выходит за папку
проекта: пути с `..`, абсолютные пути и служебные папки (`.git`,
`updates`, `logs`) отклоняются. После установки терминал нужно перезапустить.

Новый выпуск публикуется одной командой:

```powershell
python -m tools.pack_release --version 1.1.0 --date 2026-11-01 `
  --title "Терминал 1.1" --note "что изменилось" `
  --add docs/release-1.1.0.md
```

Инструмент собирает архив в `updates/feed/`, считает `sha256` и дописывает
запись в `data/releases.json`. Без `--add` публиковать нечего: патч должен
содержать хотя бы один файл проекта.

## Ограничения

- личностные матрицы пока влияют только на интерфейс, не на ответы;
- генерация кода (этап 6) не реализована;
- внешние модели требуют запущенного OpenCode и используют его
  экспериментальные эндпоинты;
- seq2seq-small обучен на небольшом датасете: смысл ответа устойчив,
  дословное совпадение с эталоном — нет;
- поиск в интернете отдаёт заголовки и короткие описания, а не пересказ
  полных страниц.
