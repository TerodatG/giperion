# DEVLOG — журнал разработки Giperion

Память проекта между сессиями. Обновляется после каждого этапа.

## 2026-10-21 — Этапы 0–3: инфраструктура, датасет, классификаторы, seq2seq

**Контекст**

- Цель: своя нейросеть «с нуля» — код моделей пишем вручную, PyTorch как вычислительный движок.
- Оба варианта важны: и понять механику, и получить живого бота.
- Железо: NVIDIA RTX 5080 (16 ГБ, Blackwell), Python 3.13.14.
- Данные: `data/intents.json` — 77 намерений, 1314 фраз (теги частично английские:
  cooking, geology, meteorology…); `data/conversations.json` — шумная история ~440 сообщений.

**План этапов**

0. Инфраструктура: PyTorch + CUDA.
1. Датасет: скрипт сбора, свой токенизатор.
2. Классификатор намерений (своя модель: embedding → свёртки → MLP).
3. Генеративная seq2seq модель с механизмом внимания (свой код).
4. Интеграция в `chatbot.py` с fallback на правила.
5. Цикл роста: непонятые фразы → разметка → дообучение.

**Выполнено**

- Этап 0: PyTorch 2.11.0+cu128 установлен, `torch.cuda.is_available()=True`,
  GPU видна: NVIDIA GeForce RTX 5080.
- Этап 1: `training/build_dataset.py` → `data/dataset/classification.json`
  (1314 примеров, 77 классов), `pairs.json` (8737 пар), `unlabeled.json` (3);
  `training/tokenizer.py` → `models/tokenizer.json` (словарь 2309 токенов:
  `<pad>`=0, `<unk>`=1, `<sos>`=2, `<eos>`=3); нормализация — `normalize_message`.
- Этап 2 v1: TextCNN (`models/classifier.pt`, 496 тыс. параметров) — val=0.189
  при train=1.000 (переобучение).
- Диагностика v1 (`training/diagnose_classifier.py`): 82% проверочных текстов содержат
  слова, не виденные в обучении (точность 11.1% на новых vs 54.2% на знакомых).
- Этап 2 v2: исправления — стратифицированное разделение по классам, аугментация EDA
  (перестановка/удаление слов ×2, только после split), AdamW (wd=1e-4), label smoothing 0.1,
  исправлен баг: max-pool «слышал» паддинг → masked pooling (`masked_max_pool` в
  `model_classifier.py`), 30 эпох. Результат: val=0.231 (train=0.974);
  знакомые слова 68.0%, новые 12.4%.
- Этап 2 v3 (char-CNN): символьный токенизатор `training/char_tokenizer.py`
  (словарь 82 символа, `models/char_tokenizer.json`, MAX_CHAR_LEN=96),
  гибридная модель `training/model_charcnn.py` — word-CNN + char-CNN
  (`models/hybrid.pt`, 653 тыс. параметров), тренер `training/train_charcnn.py`,
  диагностика `training/diagnose_hybrid.py`. Результат: **val=0.300**;
  знакомые слова 80.0%, новые 18.1% — символьная ветка обобщает
  (морфемы, опечатки, похожие корни).
- Этап 3: seq2seq с собственным вниманием Бахданау (`models/seq2seq.pt`,
  2 млн параметров): token acc 0.779, exact match 0.047, но генерации семантически
  корректные (пример: «кухня» → «я не ем, но с удовольствием обсужу еду!»).
  Урок: exact match обманчив — у каждой фразы ~7 допустимых ответов.
- Этап 4: интеграция в бота.
  - `app/core/neural_engine.py` — inference-движок: ленивая загрузка моделей,
    пороги CONFIDENCE_THRESHOLD=0.45 (ниже — работают правила) и
    GENERATION_THRESHOLD=0.6 (выше — отвечает seq2seq, между — готовый ответ
    намерения). Без моделей/PyTorch бот работает как раньше (движок → None).
  - `app/core/chatbot.py` v033: приоритеты — служебные хендлеры → точные правила
    (вкл. выученное пользователем!) → нейросеть → difflib-уточнение → unknown.
    Порядок исправлен после регрессии в 2 тестах (нейросеть перехватывала
    выученные фразы — точное знание важнее генерации).
  - Финальный train гибрида на всём датасете: `python -m training.train_charcnn --full`
    (2276 примеров с аугментацией, без val — `models/hybrid.pt` перезаписан).
  - `tools/check_neural.py` — дымовой тест: диагноз + ответ бота по фразам.
  - `training/tokenizer.py` v002: decode больше не приклеивает тире (— –).
  - Итог: 51 тест проходит; примеры — «зарплата» → work (0.91),
    «Какая погода сегодня?» → сгенерированный ответ, «люпапупу» → unknown.
- Расширение датасета перефразировками.
  - `data/phrase_candidates.json` — 185 кандидатов для 12 ключевых классов:
    сгенерированы языковой моделью, проверены человеком (отсеяно 8 дублей,

**Ключевой вывод**

- Подмена виртуальных методов на экземпляре (`widget.closeEvent = …`,
  `widget.keyPressEvent = …`) в PySide6 не перехватывает события от Qt:
  Enter не отправлял сообщение, а меню правой кнопки оставалось английским.
  Рабочее решение — `installEventFilter` (`ChatEventFilter`,
  `WindowCursorFilter`) с обработкой `QEvent.Close` / `ContextMenu` / `KeyPress`.
- Курсор растягивания у краёв нельзя ставить самому виджету-оболочке: дети
  наследуют его, и «стрелка в обе стороны» залипает на кнопках. Курсор
