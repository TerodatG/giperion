# GiperionModel

Самостоятельный проект модели **Giperion**: намерения, знания, обучение и
нейросетевой инференс. Приложение «Терминал» подключает его как пакет
`giperion_model`.

```
model/
  giperion_model/
    api.py              точка входа: intent → neural
    config.py           пути (env GIPERION_*)
    identity_matrix.py
    personality_catalog.py
    neural_engine.py    загрузка чекпоинтов и ответ
    language/           намерения и обучение фразам
    training/           датасет, токенизаторы, тренеры
    _shared/            локальная копия json_store/text_tools/action_log
  tests/                чистые тесты модели
  pyproject.toml
```

## Установка

Из корня приложения:

```powershell
python -m pip install -e model
```

Или из этой папки:

```powershell
python -m pip install -e .
```

## Пути

`config.py` берёт каталоги из окружения, по умолчанию — текущая папка:

| Переменная | По умолчанию |
|---|---|
| `GIPERION_HOME` | текущая папка |
| `GIPERION_DATA_DIR` | `$GIPERION_HOME/data` |
| `GIPERION_MODELS_DIR` | `$GIPERION_HOME/models` |
| `GIPERION_LOGS_DIR` | `$GIPERION_HOME/logs` |
| `GIPERION_DEVICE` | `auto` (`cuda` при наличии, иначе `cpu`) |

Пустая переменная окружения считается незаданной. Если `GIPERION_HOME`
не задан, по умолчанию берётся текущая папка — для тренировочных
команд запускайте их из корня приложения или задайте пути явно.

Приложение при старте выставляет эти переменные по своим путям, поэтому
данные и чекпоинты остаются общими. Модель читает их при импорте:
выставляйте `GIPERION_*` до первого `import giperion_model`.

## Тесты

```powershell
python -m pytest model/tests
```

Сейчас тесты не импортируют `terminal` и приложение. Тестовые
`intents.json` и матрицы личности лежат в `model/tests/fixtures` и
подставляются автоматически, поэтому тесты не читают `data/`
приложения. Запускать можно из корня приложения или из `model/`.

## Чекпоинты

`neural_loader` и тренеры загружают `.pt` только с `weights_only=True`:
pickle-код из чекпоинта не исполняется. Текущие `hybrid.pt` и
`seq2seq.pt` читаются в этом режиме без переобучения. Чекпоинты
по-прежнему нужно брать из доверенного каталога: подмена весов меняет
ответы, даже если код не выполняется.

Переобучение seq2seq можно провести в отдельный файл:

```powershell
$env:GIPERION_SEQ2SEQ_OUTPUT = "models/seq2seq_new.pt"
$env:GIPERION_SEQ2SEQ_ONE_RESPONSE = "1"  # опционально
python -m giperion_model.training.train_seq2seq
$env:GIPERION_SEQ2SEQ_FILE = "models/seq2seq_new.pt"
python -m tools.eval_generation --limit 200
```

Эксперименты дали 0.896 (обычное переобучение) и 0.904
(один ответ на паттерн) против 0.921 у рабочей модели, поэтому
`seq2seq.pt` не заменялся. Beam search (3 луча) на текущей выборке
дал 0.888 против 0.880 у жадного — разница в пределах шума,
поэтому в рантайме остаётся жадное декодирование с запретом повторов.

Пороги по классам пробовали отдельно: OOF-подбор дал покрытие 0.805
при точности 0.923 против 0.803/0.924 у общего порога. Выигрыша нет,
поэтому per-class пороги не внедрялись.

## Линейный роутер

Если рядом с чекпоинтами лежит `linear_intent.json`, движок сначала
спрашивает его, а CNN остаётся запасным вариантом. Роутер считает
char n-grams и логистическую регрессию на чистом Python: sklearn нужен
только для обучения.

```powershell
python -m tools.train_linear_intent
python -m tools.eval_intent_model --router --fail
```

Артефакт хранится в `models/` приложения и в пакет не входит.

На отложенном наборе из 2310 фраз (20 natural и 10 template на
класс) роутер даёт top-1 **0.870** и macro-F1 **0.874** на natural-
подвыборке. При пороге 0.50 покрытие составляет **0.760**, точность
на покрытых — **0.948**. На template-подвыборке — 0.912/0.917.
CNN на natural-наборе даёт 0.553/0.564, поэтому остаётся только
запасным вариантом.

CNN остаётся запасным вариантом: эксперимент с весами классов
(`python -m giperion_model.training.train_charcnn --balanced`) дал
0.538 top-1 против 0.553 у обычной модели, поэтому рабочую
`hybrid.pt` не заменяли. По умолчанию CNN не загружается;
включить её можно через `GIPERION_USE_CNN=1`. Оценить чекпоинт
можно через `python -m tools.eval_intent_model --model <путь>`.

## Граница

- `giperion_model` **не импортирует** `terminal` и не знает про агента.
- `shared` и `config` приложения не используются: пути — в
  `giperion_model.config`, три общих модуля скопированы в `_shared`.
- Приложение использует как фасад `giperion_model.api`, так и несколько
  внутренних модулей (`identity_matrix`, `language.*`,
  `neural_engine`, `personality_catalog`, `training.*`). Это
  зафиксированный на сегодня контракт; при выносе в отдельный
  репозиторий меняйте их вместе с приложением.

## Отдельный репозиторий

Папка самодостаточна по коду: у неё свой `pyproject.toml`, тесты и
`.gitignore`. Данные, токенизаторы и чекпоинты (`data/`, `models/`)
исключены из git — их нужно перенести отдельно или собрать заново.
Чтобы вынести в отдельный репозиторий, скопируйте `model/`, выполните
`git init` и передайте приложению `pip install -e <путь>`.
