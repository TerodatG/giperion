# DEVLOG 2026-10-25 · часть 7

## 2026-10-25 — браузер как инструмент: fetch_url

**Выполнено**

- `terminal/core/agent/web.py`:
  - `validate_url()` приводит адрес к http/https, запрещает `file://`,
    нестандартные порты (только 80/443) и логин/пароль в URL;
  - `is_public_host()` резолвит имя и блокирует localhost, приватные,
    канальные, служебные и multicast-адреса — простая защита от SSRF;
  - `fetch()` делает один GET с таймаутом 15 с и лимитом 400 КБ,
    определяет кодировку из `Content-Type`, превращает HTML в текст
    через `html.parser` (без script/style), обрезает до 12k символов и
    добавляет «источник: …»;
  - `preview()` показывает адрес и домен, не ходя в сеть.
- Инструмент `fetch_url` (risk `exec`) — требует подтверждения:
  - ключ разрешения `web:<домен>`, поэтому «Больше не спрашивать этот
    сайт» действует только на конкретный домен;
  - в окне подтверждения домен и адрес видны до запроса;
  - без галочки «Разрешить чтение веб-страниц» инструмент отказывает.
- Правило в промпте: внешнюю документацию читать через `fetch_url`,
  если веб разрешён.
- Страницы проходят через тот же `guard.py`: «игнорируй инструкции» с
  сайта помечается как данные и даёт шаг `security`.

**Проверено**

- `python -m pytest tests/test_agent_web.py -q` — **11 passed**:
  нормализация и запреты URL, приватные адреса, очистка HTML, блок
  localhost, успешное чтение, предпросмотр, выключенный веб, работа
  через реестр, ключ по домену, подтверждение в цикле, внедрение со
  страницы.
- Живые проверки: `web.fetch("https://example.com")` вернул текст
  страницы; задача агенту «вызови fetch_url … перескажи» прошла
  подтверждение «Открыть страницу», прочитала сайт и ответила за 5.5 с
  (5.8k токенов).
- `compileall` — ok.

**Ограничения**

- Это не браузер: нет JavaScript, авторизации, cookies и переходов по
  ссылкам. Динамические сайты отдадут пустой или неполный текст.
- Один GET на вызов; страницы больше 400 КБ обрезаются, текст — 12k
  символов.
- Домен проверяется по DNS при запросе, но между проверкой и
  подключением возможен DNS-rebinding — для локального агента риск
  признан приемлемым.
- Модель не всегда сама выбирает `fetch_url`: в первом живом прогоне
  она позвала подагента и ответила про README; по прямой просьбе
  «вызови fetch_url» сработало сразу. Формулировка задачи важна.
- Веб по умолчанию выключен; в `data/agent_settings.json` флаг
  `browser_enabled` после проверок возвращён в `false`.

## 2026-10-25 — наблюдатель за файлами

**Выполнено**

- `terminal/core/agent/watch.py`:
  - `snapshot()` обходит проект и запоминает `mtime_ns` и размер файлов;
    игнорирует `data`, `.git`, `.agent_worktrees`, `assets`, скрытые
    файлы и временные `.agent-tmp`, лимит 50 000 файлов и 2 МБ на файл;
  - `diff()` находит новые, изменённые и удалённые файлы, ограничивает
    списки 20 записями;
  - `Watcher` опрашивает проект в отдельном потоке, копит изменения,
    ждёт паузы (debounce) и только потом вызывает обработчик; после
    вызова держит cooldown и переснимает базовый снимок, чтобы правки
    самого агента не будили его по кругу;
  - настройки — `data/agent_watch.json` (интервал, пауза, отдых,
    задача, авто-запуск) с подрезкой значений.
- Окно **«Наблюдатель…»** (кнопка в окне агента):
  - интервал опроса, пауза и отдых в секундах, текст задачи, галочка
    «Запускать задачу автоматически (только чтение)»;
  - журнал: начало наблюдения, найденные изменения, результат задачи;
  - изменения из потока попадают в окно через Qt-таймер, а не напрямую;
  - авто-запуск создаёт `AgentJob` с `policy="read"`, четырьмя шагами и
    общим бюджетом; модель — провайдер, иначе помощник;
  - закрытие окна останавливает поток и отменяет задачу.

**Проверено**

- `python -m pytest tests/test_agent_watch.py -q` — **6 passed**:
  игнор служебных папок, все виды различий, слияние, доставка события,
  cooldown, настройки с границами.
- `python -m pytest tests/test_agent_watch_ui.py -q` — **4 passed**:
  старт/стоп, запись изменений без авто-запуска, отсутствие модели,
  обработка изменений из потока в окне.
- Живой прогон: наблюдение за временной папкой с интервалом 1 с;
  появился `b.txt` → через паузу «изменения (1): новые: b.txt» →
  авто-задача прочитала `a.txt` и `b.txt`, ответила про строки за 11 с.
- `compileall` — ok.

**Ограничения**

- Это опрос, а не события ОС: изменения замечаются с задержкой до
  интервала, а debounce добавляет ещё паузу.
- Авто-запуск всегда read-only: писать по изменению файлов агент не
  будет, это осознанное ограничение.
- Cooldown обязателен: без него правки агента запускали бы новые
  проверки; при коротком cooldown и долгой задаче возможен повторный
  запуск после её завершения.
- Сравнение идёт по `mtime` и размеру, поэтому правка с тем же размером
  в пределах одной наносекунды теоретически может остаться незамеченной.
- Наблюдается один корень — `BASE_DIR`; worktree параллельных задач не
  отслеживаются.
- Кнопка «Наблюдатель…» живёт в окне агента; отдельной карточки в
  «Мастерской» нет.

## 2026-10-25 — AppContainer для плагинов: настоящая граница ОС

**Выполнено**

- `terminal/core/agent/container.py`:
  - `prepare()` копирует Python (`sys.base_prefix`) в

  - `grant()` даёт контейнеру чтение проекта (`terminal`, `shared`,
    `giperion`, `docs`, `tests`, `tools`, файлы корня,

    соблюдает таймаут; окружение — родительское без секретов;

**Ограничения**

- В режиме AppContainer плагины не могут писать в проект: ACL даёт
  только чтение. Это цена настоящей изоляции; для записи есть режим
  «Процесс + сторож».
- Нужна отдельная копия Python (~93 МБ) и одноразовая выдача ACL на
  папки проекта; при обновлении Python — `--prepare --force`.
- Сеть в контейнере не запрещена на уровне ОС: у AppContainer нет
  интернет-возможности, но и явного запрета нет — сеть блокирует
  аудит-хук, а не ОС.
- AppContainer работает только на Windows; на других ОС режим
  недоступен.
- Копия Python и ACL переживают удаление папки проекта: перед переносом
  стоит выполнить `--remove`.
