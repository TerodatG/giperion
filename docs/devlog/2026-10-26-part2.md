# DEVLOG 2026-10-26 · часть 2

## 2026-10-26 — смысловой поиск: BM25 и локальные эмбеддинги

**Выполнено**

- `terminal/core/agent/semantic_text.py` — токенизация и стемминг:
  `camelCase`/`snake_case` делятся на части, стоп-слова выбрасываются,
  русские окончания срезаются грубо (`подтверждения` → `подтвержд`),
  чтобы падежи совпадали в BM25.
- `semantic_index.py` — фрагменты проекта: функции, методы, классы и
  шапка модуля (docstring или первые комментарии), разделы markdown,
  окна по 60 строк для остального текста. `data/`, `archive/` и worktrees
  не индексируются. Кеш — `data/agent_semantic.json` со снимком
  `mtime_ns` и размеров: перестройка при изменении файлов, без таймера.
- `semantic.py` — BM25 (`k1=1.5`, `b=0.75`); верхние 80 кандидатов
  переранжируются косинусом: `0.65 × близость + 0.35 × BM25`. Веса
  путей: `tests/` — 0.7, `docs/` — 0.92. Итоговые баллы нормированы
  в 0..1.
- `embeddings.py` — OpenAI-совместимый `/embeddings` только для
  локального адреса (`localhost`, `127.0.0.1`, `::1`). Модель берётся
  из настройки или ищется в `/models` по словам `embed`, `bge`, `e5-`,
  `gte-`; батч, проверка числа векторов, косинус, таймаут параметром
  (без глобального состояния).
- Инструмент `find_relevant` (risk `read`) добавлен в каталог и реестр;
  подсказка — в обоих системных промптах. Ответ: путь, строка, тип,
  имя символа и отрывок.
- «Провайдер…»: галочка «Смысловой поиск по проекту» и поле «Модель
  эмбеддингов». Настройки — `semantic_search`, `embedding_model`;
  сохранение сбрасывает кеши.
- Векторы кешируются по хешу текста в `data/agent_vectors.json`
  (до 4000 записей), чтобы правка файла не сбрасывала весь кеш. Оба
  файла — в `.gitignore`.
- Стенд: задача `semantic-embeddings` с `inspect`, который проверяет и
  вызов `find_relevant`, и названный файл. Уточнены формулировки
  `two-files`, `docs-passport`, `web-fetch-word`,
  `find-command-whitelist` и добавлен запас шагов.

**Проверено**

- Живой проект: 356 файлов, 3060 фрагментов, кеш 5.5 МБ; тёплый запрос
  1.2–2.9 с, первый холодный — около 5 с:
  - «изоляция плагинов в отдельном процессе» → `plugin_runner.py`
    (module), затем `docs/agent_tools.md`;
  - «mcp allowlist domains for url arguments» →
    `mcp_policy.py: check_domains` и `domain_allowed`;
  - «где в проекте описан смысловой поиск и эмбеддинги» →
    `semantic.py` (module);
  - без эмбеддингов (BM25-only) те же три запроса дают те же верхние
    ответы, только медленнее по смыслу на перефразировках.
- Эмбеддинги: `text-embedding-nomic-embed-text-v1.5` через LM Studio
  (`/v1/embeddings`), 423 вектора после серии запросов, файл 4.6 МБ.
- Модульные тесты: 19 новых (токены, стемминг, чанки, BM25, гибрид,
  fallback, кеш, веса путей, клиент эмбеддингов, косинус); полный прогон
  на момент коммита семантики — **614 passed**, структура 0/0/0,
  `compileall` ok.
- Стенд: пять полных прогонов — 20–21 из 22 (типично **21/22, 96 %**).
  `semantic-embeddings` — **5/5**, 3–7 шагов, 6–33k токенов. Каждый раз
  проваливается другая старая задача (`docs-passport`, `docs-plugins`,
  `architecture-agent-section`, `web-fetch-word`), и каждая по
  отдельности проходит: это разброс локальной модели, а не регрессия.
  Базовые цифры обновлены в `docs/architecture.md`.

**Ограничения**

- Эмбеддинги только локальные: при удалённом провайдере код не уходит
  наружу, но остаётся BM25.
- Переранжируются только 80 кандидатов BM25; фрагмент, не попавший в
  них, не найдётся даже по смыслу.
- Стемминг грубый: возможны ложные склейки редких словоформ.
- `data/` исключён из смыслового индекса — конфиги и журналы ищутся
  через `search_text`.
- Первый запрос после смены модели или массовой правки файлов дольше:
  считаются векторы кандидатов.
- Кеш фрагментов (5.5 МБ) и векторы растут; оба лежат в `.gitignore`.
