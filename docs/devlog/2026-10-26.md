### Надёжность и наблюдаемость

- **Таймаут шага**: настройка `step_timeout` (по умолчанию 180 с, 0 —
  без лимита) и поле «Таймаут шага» в «Провайдере». Вызов модели идёт
  в отдельном потоке; если он не уложился, задача останавливается с
  шагом «Таймаут шага». Уже отправленный HTTP-запрос не прерывается,
  но цикл его не ждёт.
- **Повтор пустого ответа**: `NativeBrain._complete` повторяет запрос
  один раз, если провайдер вернул ни текст, ни вызовы; после повтора —
  понятная ошибка.
- **Окно трейса**: кнопка «Трейс…» в окне агента открывает полный

### Контекст: бюджет из модели и умный индекс

- **Бюджет из модели.** `context_budget.py` переводит контекст модели в
  бюджет символов: `токены × 2.5 × 0.75` (запас 25 % на ответ), границы
  8k–2M. Значения каталога меньше 2000 считаются тысячами: `32` → 32k
  токенов → 60 000 символов, `200000` → 375 000 символов. В окне агента
  появилась галочка «Из модели» (`context_auto`, по умолчанию включена);
  если модели нет в каталоге — берётся ручное поле. Настройка
  сохраняется кнопкой «Запомнить».
- **Индекс по mtime.** `index.py` больше не ждёт пятиминутный TTL:
  перед использованием сравнивает `mtime_ns` и размеры файлов из
  снимка; при изменении перестраивается. Сам `agent_index.json`
  исключён из снимка, иначе он считался бы вечной правкой.
- **Документация в индексе.** Заголовки markdown (`# … ######`) стали
  символами вида `section`, поэтому `find_symbol("AppContainer")`
  находит разделы в `docs/*.md`, а не только функции.

- `data/agent_mcp.json` указывает на `python.exe -m mcp_server_fetch`

- Проверено на двух уровнях:
  - `McpClient`: `initialize`, `tools/list` (инструмент `fetch`, схема

### MCP-allowlist и общий план с подагентами

- **MCP-allowlist.** В `data/agent_mcp.json` у сервера появились два
  необязательных поля:
  - `tools` — белый список инструментов; остальные не попадают в схемы
    модели;
  - `domains` — домены для URL-аргументов (`url`, `uri`, `href`,
    `link`), точное имя или `*.example.com`; запрещённый домен
    отсекается до `tools/call`.
- Проверено на живом `mcp-server-fetch`: `example.com` читается,
  `python.org` отклоняется с «Домен не разрешён для MCP «web»», а
  `_tool_allowed(..., "write_file")` возвращает `False`.
- **Общий план.** `_RunState.plan` хранит актуальный чек-лист; при
  `ask_subagent` он передаётся каждой подзадаче как «Общий план задачи»
  с отметками `[x]/[>]/[ ]`. Подагенты не меняют план сами — обновляет
  его родитель по их находкам, поэтому несколько агентов работают по
  одному плану без гонок.

**Проверено**

- Тесты: разбор `tools`/`domains`, фильтр инструментов, точные и
  wildcard-домены, блокировка запрещённого домена, передача плана в
  промпт подагента.
- `python -m pytest` — 594 passed; `check_structure --strict` — 0/0/0;
  `compileall` — ok.
- **Разделение `mcp.py`.** Конфиг и политика (тип `McpServer`,
  `load_servers`, `_tool_allowed`, `domain_allowed`, `check_domains`)
  переехали в `mcp_policy.py` (202 строки), клиент остался в `mcp.py`
  (451 строка). `mcp.load_servers` — тонкая обёртка, которая передаёт
  текущий `mcp.CONFIG_FILE`, поэтому стенд и тесты с подменой пути
  работают как раньше; `mcp.McpServer`, `mcp.domain_allowed` и
  `mcp._safe_name` остались доступны через реэкспорт.

**Ограничения**

- `domains` проверяет только явные URL-аргументы: если сервер принимает
  адрес внутри другого поля, ограничение не сработает.
- `tools` действует на уровне списка инструментов, а не отдельных
  операций внутри одного инструмента.
- Подагенты видят план на момент запуска; обновления родителя после
  этого они не получают.
- Параллельные подагенты не синхронизируют свои шаги между собой —
  только читают общий план.
