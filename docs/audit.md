# Аудит, хранение и права

Журнал агента — `data/agent_audit.jsonl`. Это JSONL с хеш-цепочкой:
каждая запись содержит `prev` и `hash`, поэтому удаление, вставка или
правка строки ломает проверку.

## События

| Событие | Когда пишется | Полезная нагрузка |
| --- | --- | --- |
| `run.start` | старт задачи верхнего уровня | задача (300 символов), корень |
| `approval` | решение пользователя | инструмент, `approved`, `remember`, цель |
| `denied` | действие запрещено политикой | инструмент, причина |
| `tool` | инструмент выполнен | инструмент, риск, `ok`, размер, цель |
| `run.finish` | задача завершена | успех, ошибка, отмена, число шагов |
| `run.error` | исключение в цикле | тип и текст ошибки |
| `audit.rotate` | архивация старых записей | имя архива и число записей |

Секреты в строках полезной нагрузки вырезаются тем же редактором, что и
в промпте (`[скрыто]`). Токен API и ключи провайдера в журнал не
попадают.

## Проверка и экспорт

```powershell
python -m tools.audit_log --check
python -m tools.audit_log --tail 20
python -m tools.audit_log --search "write_file"
python -m tools.audit_log --export data/audit-export.jsonl
python -m tools.audit_log --verify-export data/audit-export.jsonl
```

Экспорт кладёт рядом `.sig` с HMAC-SHA256. Ключ — `data/audit_export.key`
(создаётся при первом экспорте, права 0600); его нужно хранить отдельно
от журнала. Подмена любой строки экспорта или подписи даёт ошибку.

Фильтры `--since` и `--until` принимают ISO-дату или начало строки
времени (`2026-10-27`).

## Срок хранения

По умолчанию журнал не чистится. Ротация:

```powershell
python -m tools.audit_log --prune 90
```

Записи старше 90 дней переносятся в
`data/agent_audit-YYYYMMDD-HHMMSS.jsonl`, а активный журнал начинается с
события `audit.rotate`; оставшиеся записи пересобирают цепочку от него.
Старый экспорт и архив продолжают проверяться своими подписями.
Рекомендуемый срок — 90 дней для рабочих станций и 365 для
регулируемых проектов.

## Матрица прав

Политика задаётся на задачу (`read`, `confirm`, `trust`). Риск
инструмента — в его описании (`registry_catalog.py`).

| Риск | `read` | `confirm` | `trust` |
| --- | --- | --- | --- |
| `read` | разрешено | разрешено | разрешено |
| `network` | запрещено | подтверждение | подтверждение |
| `write` | запрещено | подтверждение | разрешено, кроме `git_commit` |
| `exec` | запрещено | подтверждение | подтверждение |
| `mcp` | запрещено | подтверждение | подтверждение |
| `plugin` | запрещено | подтверждение | подтверждение |

Опасные действия (`git_commit`, `git_restore`, `run_command`,
`run_tests`, `browser_act`, `fetch_url`) не обходят подтверждение даже
при `trust`, если это явно не разрешено отдельной галочкой. Запись
файлов при `trust` всё равно показывает дифф в панели подтверждения,
если панель открыта; для полного запрета используйте `read`.

## Секреты

`python -m tools.scan_secrets` проверяет файлы проекта на токены,
пароли и приватные ключи. В рантайме `redact` вырезает их из
наблюдений, памяти, аудита и журнала API. Если секрет всё же попал в
историю, удалите его из файлов и ротируйте ключ: аудит покажет, кто и
когда к нему обращался.
