# Песочница команд агента

`run_command` и `run_tests` выполняются не напрямую из процесса Терминала,
а через `terminal/core/agent/exec_sandbox.py`.

## Что делается всегда

- команда запускается без shell, только из белого списка
  `validate_command`;
- окружение чистое: секреты, токены и прокси родителя не наследуются;
- `HTTP_PROXY`/`HTTPS_PROXY` указывают на мёртвый `127.0.0.1:9`,
  `GIPERION_EGRESS=deny`, git не спрашивает пароль;
- на Windows процесс сажается в Job Object с лимитом 1 ГБ и 60 с CPU;
- таймаут — 300 с, вывод обрезается до 4 000 символов;
- рабочая папка — корень проекта, команда не получает путь наружу;
- успешный результат кешируется на 60 с, если файлы проекта не
  изменились: повторная команда не выполняется второй раз.

## Режимы

Настройка `command_sandbox` в `data/agent_settings.json`:

| Режим | Поведение |
| --- | --- |
| `process` | всегда процесс с Job Object и чистым env |
| `auto` (по умолчанию) | Python-команды и git — в AppContainer, если он готов; иначе процесс |
| `appcontainer` | только AppContainer; без подготовки — ошибка |

Подготовка AppContainer (Windows):

```powershell
python -m tools.setup_plugin_container --prepare
```

В AppContainer у команды нет сети и записи в проект: доступно чтение
`terminal`, `shared`, `docs`, `tests`, `tools`, `knowledge`, `model`,
`skins`, `.git` и запись только во временную папку. Для pytest
отключается кеш (`-p no:cacheprovider`), байткод не пишется. Git
запускается в отдельном профиле `Giperion.Agent.Command`: каталог Git
доступен только на чтение, сеть отсутствует.

## Ограничения

- AppContainer доступен только на Windows. На Linux/macOS остаётся
  процесс с Job Objects/rlimit и прокси-заглушкой.
- Прокси-заглушка блокирует HTTP-клиенты, но не сырые сокеты; полную
  сетевую изоляцию даёт только AppContainer (и то для Python-команд).
- `git` запускается процессом: AppContainer не выдаёт чтение
  `Program Files`, а копировать git внутрь контейнера слишком дорого.
  Для git действуют Job Object, чистый env и запрет интерактивного
  ввода.
- Команда всё ещё может изменить файлы проекта, если это разрешённая
  команда (`compileall`, `pytest`): запись ограничена правами процесса,
  а не отдельным ACL. Для строгого режима используйте `read`-политику и
  AppContainer.
