# Плагины инструментов агента

Плагины позволяют добавить агенту «Терминала» собственный инструмент.
Они **выключены по умолчанию** и включаются вручную в окне агента:
«Провайдер…» → галочка **«Разрешить плагины инструментов»**.

## Где лежат

`data/agent_tools/*.py` — один файл на плагин. Файлы, начинающиеся с `_`,
игнорируются. Имя инструмента должно быть уникальным и не совпадать со
встроенными.

## Шаблон

```python
from terminal.core.agent.protocol import ToolResult


def handler(root, args):
    path = args.get("path", "")
    return ToolResult(True, f"Плагин получил путь: {path}")


TOOL = {
    "name": "my_tool",
    "description": "Короткое описание для модели.",
    "args": {
        "path": "что означает аргумент",
    },
    "required": ["path"],
    "risk": "read",          # read | write | exec
    "handler": handler,
}
```

## Правила

- `args` — словарь «имя → описание», все аргументы строки.
- `required` — какие аргументы обязательны.
- `risk`:
  - `read` — выполняется без подтверждения;
  - `write` — требует подтверждения пользователя;
  - `exec` — требует подтверждения пользователя.
- `handler(root, args)` возвращает `ToolResult(ok, text)`. Исключение
  внутри обработчика показывается агенту как ошибка инструмента.
- Агент видит описание и схему автоматически: `tool_schemas()` включает
  плагины.

## Безопасность

**Плагин — это Python-код.** Он выполняется в процессе Терминала с его
правами, поэтому:

- не включайте плагины, которым не доверяете;
- не берите плагины из интернета без чтения кода;
- проверяйте, что обработчик не выходит за папку проекта, если это
  read-инструмент;
- write/exec-плагины всё равно проходят через подтверждение, но
  read-плагины — нет.

После сохранения настроек реестр плагинов перезагружается без
перезапуска приложения.
