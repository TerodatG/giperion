# Смысловой поиск по проекту

Инструмент `find_relevant` ищет не точную строку, а место, где о задаче
говорится по смыслу. Он дополняет `search_text` (подстрока) и
`find_symbol` (имя функции).

```
find_relevant(query="где проверяются подтверждения записи файлов", limit=8)
```

Ответ — список фрагментов с путём, номером строки, типом, именем символа
и отрывком:

```
- terminal/core/agent/semantic.py:1 [module] semantic.py (0.78)
  Смысловой поиск: BM25 по фрагментам и переранжирование эмбеддингами…
```

## Как это устроено

1. **Фрагменты.** Проект делится на небольшие куски:
   - Python — функции, методы, классы и шапка модуля (docstring или
     первые комментарии);
   - markdown — каждый раздел с заголовком;
   - остальной текст — окна по 60 строк.
   Служебные каталоги (`data/`, `archive/`, worktrees) не индексируются.
2. **BM25 по словам.** Запрос и тексты токенизируются: `camelCase` и
   `snake_case` делятся на части, стоп-слова выбрасываются, русские
   окончания грубо срезаются (`подтверждения` → `подтвержд`), чтобы
   падежи совпадали. Небольшой словарь синонимов связывает русские и
   английские основы (`плагин` ↔ `plugin`, `подтверждение` ↔ `approval`).
3. **Эмбеддинги.** Верхние 10 кандидатов BM25 переранжируются косинусом
   (`0.85 × BM25 + 0.15 × близость`), а сильные смысловые находки вне
   BM25 добавляются с весом до 0.3. Косинус нормируется min-max по
   выдаче, поэтому «высокий фон» эмбеддингов не перебивает точные слова.
   Векторы берутся у локального OpenAI-совместимого провайдера через
   `/embeddings`.
4. **Глубокий индекс.** `tools/build_semantic_index.py` заранее считает
   векторы для всех фрагментов проекта. Тогда косинус участвует в поиске
   по всему проекту, а не только по словам:

   ```powershell
   python -m tools.build_semantic_index --check   # покрытие
   python -m tools.build_semantic_index           # досчитать всё
   python -m tools.build_semantic_index --limit 500 --batch 16
   ```

   Команда докачивает только отсутствующие векторы и пишет кеш по ходу,
   поэтому её можно прервать и продолжить. Ответ `find_relevant`
   показывает покрытие: `эмбеддинги «…», 3397/3397 фрагментов`.
5. **Веса путей.** Фрагменты из `tests/` получают коэффициент 0.5, из
   `docs/` — 0.75: код проекта выше тестов и журналов при равном
   совпадении.

## Настройки

В окне «Провайдер…»:

- **«Смысловой поиск по проекту»** (`semantic_search`, по умолчанию
  включён);
- **«Модель эмбеддингов»** (`embedding_model`): пусто — агент ищет
  модель в `/models`, в имени которой есть `embed`, `bge`, `e5-` или
  `gte-`.

Эмбеддинги используются, только если адрес провайдера локальный
(`localhost`, `127.0.0.1`, `::1`). Иначе остаётся BM25 — код не
отправляется в облако.

## Кеши

- `data/agent_semantic.json` — фрагменты и снимок `mtime_ns`/размеров
  файлов (около 5 МБ на этом проекте);
- `data/agent_vectors.db` — SQLite-кеш векторов (float32) по хешу текста
  для текущей модели, ограничен 4000 записей; старый
  `agent_vectors.json` переносится автоматически.

Индекс перестраивается, когда изменились файлы, — без ожидания таймера.
Векторы кешируются по содержимому фрагмента: правка файла меняет только
его куски.

## Очистка и проверка

```powershell
python -m tools.clean_caches --check   # размеры кешей
python -m tools.clean_caches --yes     # удалить и перестроить
python -m tools.eval_retrieval         # hit@1 и hit@5 на наборе запросов
python -m tools.eval_retrieval --fail  # код 2, если есть промахи
```

`eval_retrieval` использует `tools/retrieval_cases.py`: восемь запросов
с ожидаемыми файлами. Текущий результат на BM25+синонимах — **hit@5 =
8/8**; с эмбеддингами — тоже 8/8, hit@1 около 4–5/8.

## Ограничения

- BM25 ищет слова; эмбеддинги добавляют кандидатов по смыслу. Если
  глубокий индекс не построен, векторная часть видит только фрагменты,
  которые уже встречались в запросах.
- Русский стемминг грубый: редкие словоформы могут склеиться неверно.
- Первый запрос с новой моделью медленнее (векторы ещё не посчитаны);
  дальше — около 1–3 с на запрос на этом проекте.
- `build_semantic_index` требует локального провайдера и считает
  ~3000 фрагментов около минуты (на этом проекте 2742 вектора за
  55.8 с); кеш до 4000 записей.
- `find_relevant` только читает; запись и команды по-прежнему требуют
  подтверждения.
